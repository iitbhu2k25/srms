# SRMS — SMART RIVER MONITORING SYSTEM (VARUNA RIVER BASIN)

**Integrated Intelligent River Health Monitoring and Pollution Tracking System for Sustainable Rejuvenation of
Varuna River Basin** · Smart Laboratory on Clean Rivers (SLCR), IIT (BHU) Varanasi

The Centralized Digital Platform (component 2.5 of the proposal): one dashboard and API for the IoT stations,
the SMART-STREAM autonomous boat, LC-HRMS fingerprinting of emerging pollutants, TEM geophysics and drone /
bathymetric surveys. The project layout follows the Varanasi Carbon Dashboard (DashboardC).

> **All data is dummy.** It is seed data in `fast_backend/media/data` plus a deterministic simulator. It is
> loaded into PostgreSQL exactly like real data, so going live means replacing the seed files and turning
> the simulator off. No code changes are needed in the API or frontend.

How to run: see **[howtorun.txt](howtorun.txt)**.

## Database tables

| Area | Tables |
|---|---|
| Monitoring network | `stations`, `parameters`, `river_centerline_points` |
| Time series | `river_readings` (15-min, one column per parameter + device health), `well_readings` |
| Groundwater | `wells` (sited from TEM; paired with a river station) |
| SMART-STREAM boat | `boat_missions`, `boat_waypoints`, `boat_commands` |
| LC-HRMS | `campaigns`, `compounds`, `samples`, `detections`, `source_apportionment` |
| Surveys | `tem_transects` (resistivity section as JSONB), `surveys`, `hotspots`, `cross_sections` |

## API (prefix `/api`)

| Component | Endpoints |
|---|---|
| Dashboard | `GET /overview`, `GET /health-index/history`, `GET /parameters` |
| IoT stations (2.2) | `GET /stations`, `GET /stations/{id}`, `GET /stations/{id}/series?parameters=do,ph&hours=24`, `GET /stations/{id}/forecast` |
| Groundwater | `GET /groundwater/wells`, `GET /groundwater/wells/{id}/series?days=30` |
| Alerts | `GET /alerts?status=&severity=&station_id=` |
| SMART-STREAM boat | `GET /boat/status`, `POST /boat/command`, `GET /boat/commands` |
| LC-HRMS (2.4) | `GET /lab/campaigns`, `GET /lab/compounds`, `GET /lab/samples?campaign_id=`, `GET /lab/apportionment/{campaign_id}` |

| Drone & boat surveys (2.3) | `GET /surveys`, `GET /surveys/hotspots`, `GET /surveys/cross-sections` |
| Ingestion | `POST /ingest/readings` (IoT station / ESP32 unit, identified by `device_id`) |

## From dummy to real data

1. **IoT stations / ESP32 unit:** devices POST to `/api/ingest/readings` with their `device_id`
   (`stations.device_id`). Set `SIMULATE_LIVE=false` in `.env` once they report.
2. **Reference data:** replace the CSVs in `fast_backend/media/data` (real coordinates, campaigns, compounds…).
   For a fresh load, run `docker compose down -v`, then `docker compose up -d` and `./fast_backend/start.sh`.
3. **Lab, TEM, drone results:** replace the generating loaders in `script/database/lab` and `script/database/surveys`
   with loaders that read the real result files (CSV / Excel), as the Carbon Dashboard does for its survey data.
4. **Boat:** forward `boat_commands` to the on-board Raspberry Pi and store its telemetry in place of the
   simulated position (`service/boat_svc/navigation.py`).
5. **Bacterial forecast:** `service/forecast_svc.py` is a placeholder proxy until the AI model is trained.

River Health Index weights and alert thresholds (`service/health_svc.py`, `service/alert_svc.py`) are placeholders
to be agreed with the team.
